# PS‑PL软硬件任务划分技能

## 适用场景
Zynq / PYNQ图像加速项目；判断图像处理逻辑放在PL硬件还是PS处理器；避免盲目硬件加速，全系统性能不升反降。

## 使用方法
1. **适合放到PL**：高度并行逐像素无状态计算，例如颜色投影、像素差分、残差判断；简单像素级运算。
2. **保留在PS**：摄像头采集、高斯滤波、形态学运算、连通域筛选、画面渲染、流程控制、资源管理、UI交互提示。
3. 性能评估：PL仅加速像素计算；DMA搬运、缓存同步、PS后处理会引入额外开销，必须统计全链路耗时，不能只看PL核延迟。
4. 定位瓶颈：若PS渲染、图像合成占主要耗时，优先优化软件逻辑，而非压榨PL硬件。

## 失效条件
- 将连通域、复杂形态学全部放入PL，造成逻辑规模暴涨；
- 只关注PL计算延迟，忽略DMA传输、缓存、PS渲染开销；
- 全部图像处理推入PL，没有CPU参考对照路径。

## 经验来源
皮影交互系统：PL负责前景先验计算，但整机性能瓶颈来自PS皮影渲染；单纯提升PL速度无法降低系统总时延。
